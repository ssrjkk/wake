# Гайд по тестнету — фаза проверок, без единого реального доллара

Код теперь по умолчанию смотрит на тестнет (`src/lib/lighter.ts`, `signing_service.py`,
`leader_listener.py`) — не потому что «на всякий случай», а потому что это буквально
следующий пункт `IMPLEMENTATION-PLAN.md` (Фаза 1, гейт: недели чистой работы) и
`GO-LIVE-CHECKLIST.md`.

Честно: тестнет-URL (`testnet.zklighter.elliot.ai`, включая WebSocket) подтверждён
официальными источниками Lighter. Конкретную L1-тестовую сеть (почти наверняка
Sepolia — это стандарт для Ethereum-тестнетов с 2025 года, Goerli давно депрекейтнут)
я не нашёл явно названной в их публичных доках — **первый шаг ниже — не угадывать,
а посмотреть самому** в интерфейсе.

## Шаг 0 — официальный agent kit (возможно, самый быстрый путь)

У Lighter/elliottech есть готовый инструмент именно под эту задачу:
https://github.com/elliottech/lighter-agent-kit — "Agent Skill to let AI Agents trade
on Lighter", ставится в Claude Code/Cursor/Codex командой:
```
curl -fsSL https://github.com/elliottech/lighter-agent-kit/releases/latest/download/install.sh | bash
```
Сам разработчик прямо пишет: тестировать стратегии сначала на paper trading, читать
DISCLAIMER.md перед фандед-аккаунтом. Стоит попробовать ЭТО первым в Claude Code —
может закрыть часть того, что мы вручную строим в `backend/`, готовым и
поддерживаемым инструментом.

## Шаг 1 — кошелёк и сеть

1. Открой https://app.lighter.xyz, найди переключатель testnet/mainnet в интерфейсе —
   он покажет, к какой именно сети просит подключиться кошелёк. Это и есть ответ на
   вопрос «какой именно L1-тестнет», без гадания с нашей стороны.
2. Если это Sepolia (вероятнее всего): в MetaMask/любом кошельке добавь сеть Sepolia,
   если её ещё нет (в большинстве кошельков она уже встроена как тестовая сеть).

## Шаг 2 — реальные краны (не мои — официальные/известные)

**Тестовый ETH (на газ):**
- https://cloud.google.com/application/web3/faucet/ethereum/sepolia — Google Cloud, надёжный
- https://www.alchemy.com/faucets/ethereum-sepolia — Alchemy
- Chainlink Faucet — стабильно работающий, щедрые лимиты

**Тестовый USDC (маржа на Lighter — они прямо используют USDC-контракты):**
- https://faucet.circle.com — официальный кран от самого эмитента USDC, поддерживает
  Sepolia и ряд других тестнетов. Самый заслуживающий доверия вариант именно для USDC,
  так как это первоисточник.
- https://ethglobal.com/faucet/sepolia-11155111-usdc — 1 USDC/день, требует логина ETHGlobal

## Шаг 3 — регистрация на Lighter testnet

1. На https://app.lighter.xyz, в режиме testnet, подключи кошелёк с тестовыми ETH.
2. Подпиши сообщение регистрации аккаунта (это подпись, не транзакция — газ не тратится
   на этом шаге).
3. Задепозить тестовый USDC — вот здесь понадобится и тестовый ETH (газ на транзакцию
   депозита), и тестовый USDC (сам актив).
4. Сгенерируй API key на app.lighter.xyz/apikeys — **это НЕ приватный ключ кошелька**,
   отдельная сущность специально для программной торговли. Индексы 0–2 зарезервированы,
   бери с 3, как отмечено в комьюнити-гайдах.
5. `getAccountByL1Address()` из `src/lib/lighter.ts` (уже настроен на testnet по
   умолчанию) должен теперь реально найти твой account_index.

## Шаг 4 — прогнать наш код против тестнета

```bash
cd backend
cp .env.example .env    # заполнить: LIGHTER_ACCOUNT_INDEX, LIGHTER_API_KEY_PRIVATE_KEY
pip install -r requirements.txt --break-system-packages
uvicorn signing_service:app --reload --port 8787
```
Фронтенд (`npm run dev` в корне) теперь по умолчанию читает testnet-рынки и
testnet-цены — кнопка «Открыть Long/Short» реально дойдёт до signing_service,
который реально дойдёт до testnet Lighter. Настоящие тестовые деньги, ноль реальных.

Для копи-движка: `python3 leader_listener.py --leader-id ... --account-index ...`
(`WAKE_DRY_RUN=true` по умолчанию — оставь так на этом этапе, дело не в деньгах, а
в проверке, что вся цепочка вообще связывается).

## Что это доказывает, а что нет

Чистая многонедельная работа на тестнете закрывает пункты `GO-LIVE-CHECKLIST.md`
про тестирование и стабильность. Она НЕ заменяет security-аудит и HSM/KMS —
тестнет проверяет «работает ли логика», а не «безопасно ли это для чужих денег
на постоянной основе». Это разные вопросы, и чек-лист поэтому
разделяет их на разные пункты, а не сваливает в один.
